# 파일404 제작 규칙 (초안 · 2026-11-01)

표시: ✅ 이미 정한 것 · 🆕 벤치마크 6종에서 나온 제안 · ❓ 사용자가 정해야 하는 것
근거 자료: `research/benchmark/01~06`, `research/style_guide.md`(v1)

---

## 1. 채널 정체성
- ✅ 채널명 **파일404**. 한국어 미스터리·공포 다큐. 괴물·크립티드 중심, 미스터리 사건도 다룬다.
- ✅ 톤: 실제 사진, 어둡고 리얼하게. 만화·키즈 느낌 금지.
- ✅ 시그니처: 타자기 소리, 글리치 끝 화면("404 / FILE NOT FOUND"), 롱폼 끝인사 "파일404, 기록을 닫습니다."
- 🆕 차별점 한 줄: **"다들 틀리는 걸 1차 자료로 바로잡는 채널"** (경쟁 영상 네스호 10편에서 오류 19개 확인)

## 2. 편성
- ✅ **번호 = 미스터리 주제 번호** (2026-11-01 사용자 확정). 만든 순서가 아니다. 같은 주제의 쇼츠와 롱폼은 **같은 번호**를 쓴다.
  예) 네스호 쇼츠 = #002, 네스호 롱폼 = #002. 모스맨 쇼츠·롱폼 = #001. 새 주제가 나올 때만 다음 번호를 쓴다.
  끝 화면 `다음 파일 ▶ #0NN 주제` 는 같은 형식(쇼츠는 다음 쇼츠, 롱폼은 다음 롱폼)을 가리킨다.
  - 이미 올린 쇼츠(#001~#004, #006 로지, #007 빅풋)와 만들어 둔 쇼츠 #008~#015는 번호를 그대로 둔다. **#005는 비워 둔다.**
  - 롱폼은 주제 번호를 따른다: 모스맨 롱폼 #005 → **#001**, 네스호 롱폼 #016 → **#002**. 다음 롱폼은 #003 플라이트 19.
  - 새 주제는 #016부터.
- ✅ 이미 다룬 주제는 다시 만들지 않는다. 단, **쇼츠로 만든 주제의 롱폼은 예외**(사용자 지시).
- ✅ 롱폼 순서: #002 네스호(완성) → #003 플라이트 19 → #004 디아틀로프 → 로지 → 빅풋 (#001 모스맨 롱폼은 이미 있음).
- 🆕 **롱폼 위주로 간다.** 2027-02-01부터 수익화 기준이 시청시간 8,000시간으로 두 배가 되고, 쇼츠 수익은 롱폼의 3~14%다. 쇼츠는 유입 통로로 쓴다.
- 🆕 주제 고르기: 롱폼은 **물속 괴물·사라진 비행기·배**가 강하다(호수·바다 괴물 2.01배, 항공 실종 강세). 빅풋(0.53배)·추파카브라(0.33배) 같은 숲 괴물은 쇼츠로.
- 🆕 한국 연결 고리를 한 줄씩 넣는다(한국 괴물 주제 4.13배).
- ✅ **업로드 주기: 롱폼 주 1편 + 쇼츠 주 3편** (2026-11-01 사용자 확정). 매일 올리지 않는다. 쇼츠는 그 주 롱폼에서 따온 것으로, 롱폼 공개 뒤 요일을 나눠 올린다.
- ✅ **롱폼을 먼저 만들고, 쇼츠는 롱폼에서 따온다** (2026-11-01 사용자 확정 — 조사·녹음을 한 번만 하니 효율적).
  롱폼의 가장 센 50~60초 구간을 세로 9:16으로 다시 렌더한다. 쇼츠 끝 화면은 "전체 기록 ▶ 롱폼"으로 롱폼을 가리킨다.
  한 롱폼에서 쇼츠 2~3편을 뽑되, 구간이 서로 겹치지 않게 한다.

## 3. 자료 수집
- ✅ **학습 → 자료 수집 → 제작** 순서를 지킨다. 자료가 얇은 대목은 대본 전에 더 판다.
- ✅ 롱폼은 주제를 4~5갈래로 나눠 조사한다. 갈래마다 1차 자료 원문 중심, 50KB 이상.
- ✅ 표기: ✅확인된 사실 / 📰당시 증언 / 👻전설·주장 / ⚠️출처끼리 다름. 출처 코드와 확인일.
- 🆕 노트에 **"현재 결론(해결 여부)"**과 **"시청자가 정정할 만한 곳"** 두 칸을 둔다.
- 🆕 같은 주제 경쟁 영상 상위 5~10편을 보고 **그들이 틀리는 것 / 아무도 안 다룬 것**을 먼저 뽑는다.

## 4. 대본
- ✅ 사실은 단정, 전설·주장은 "~라고 합니다 / ~했다고 주장했죠".
- ✅ 어미 비율: ~습니다 55% / ~죠 20% / ~는데요 20% / 질문 조금. "~는데요" 다음에 반전.
- ✅ 첫 1초 안에 훅. 채널 인사·"여러분"으로 시작하지 않는다. 구독 요청은 말로 하지 않는다.
- ✅ 과학 반론은 65~80% 지점. 마지막 말은 미스터리에 준다.
- 🆕 롱폼 구조: 콜드오픈(40~60초)에 **큰 질문 하나**를 심고 끝에서 회수. 막마다 작은 답 하나 + 끝에 클리프행어.
- 🆕 '이미 풀린 사건'은 결론을 숨기지 않는다. 마지막 질문은 **"결론이 설명하지 못한 한 가지"**로 좁힌다.
- 🆕 영상마다 구조 유형을 바꾼다(전설 해체형 / 사건 재구성형 / 수수께끼 연쇄형). 직전 2편과 같은 유형 금지.
- 🆕 금지: 희생자 1인칭 재연, 시신·부상의 해부학적 묘사, '충격·잔혹' 같은 쇼크 단어(광고 제한).
- 🆕 동물에 '시신' 대신 '사체', 영어 학술어는 처음에 원어 병기, 단위 환산 확인.

## 5. 길이와 속도
- ✅ 쇼츠 60초 안팎 (롱폼에서 따온다).
- ✅ 롱폼 **20~25분** (2026-11-01 사용자 확정). 기묘한 밤 최근 1년 15~20분 영상이 7~10분의 2배(49만 vs 23만).
  - 분량 기준: 말 속도 5.4음절/초 → 22분 ≈ 7,000음절. 고유 사진 약 150~180장. 챕터 카드 4~5개(4~5분마다).
  - 자료 수집도 그만큼 늘린다: 주제를 6~8갈래로 나눠 조사한다. 늘려서 채우지 않는다 — 자료가 모자라면 더 판다.
- 🆕 말 속도 목표 **초당 5.4음절**(지금 4.8, 경쟁 채널 5.8). 목소리 자체는 경쟁 채널과 같은 빠르기라서, 차이는 **쉼**에서 난다.
  - 문장 끝 쉼 0.8초 → 0.45초, 장면 사이 쉼 0.5초 → 0.35초 (목소리 톤 변화 없음)
- ✅ **목소리 6% 빠르게** (2026-11-01 사용자 확정). `VOICE_RATE` +38% → +46%, 저음화 0.86은 그대로라 음높이는 같다. 쉼 줄이기와 함께 적용.

## 6. 화면
- ✅ 사진 라이선스는 **퍼블릭 도메인 / CC0 / CC BY / CC BY-SA만**. "No restrictions"·NC·ND·불명은 쓰지 않는다.
- ✅ 저작권이 살아 있는 필름·영상 정지 화면은 쓰지 않고, '재현'이나 "보여 드릴 수 없습니다(404)"로 처리한다.
- ✅ 다시 만든 화면에는 '재현', 같은 종류의 다른 사진에는 '자료 사진' 표시.
- ✅ 자막은 아래쪽, 제목 띠는 쇼츠에서는 계속, 롱폼에서는 처음 11초만.
- ✅ **롱폼 제목 띠에 `· FULL FILE` 꼬리표** (2026-11-01 사용자 확정): `File404 · #002 네스호의 괴물 · FULL FILE`. 쇼츠는 꼬리표 없이 `File404 · #002 네스호의 괴물`.
- 🆕 롱폼 사진 **10분당 고유 70~85장**(20~25분이면 150~180장). 같은 사진은 2번까지(첫 장면 = 끝 장면만 3번), 다시 나오는 시간이 영상의 10%를 넘지 않게.
- 🆕 줌을 지금의 절반으로(장면 길이 × 1.2%). 장면 4개마다 줌인 2 · 줌아웃 1 · 정지 또는 옆으로 이동 1. 빠른 줌은 충격 장면에만.
- 🆕 장면 전환의 30~40%는 끊어 넘기기(하드컷). 지금은 97%가 흐리게 넘어가서 슬라이드쇼처럼 보인다.
- 🆕 사진을 조금 밝게(평균 밝기 54 → 62~70). 휴대폰에서 사진 내용이 보여야 '실제 사진'의 힘이 산다.
- 🆕 롱폼의 긴 정적: 콜드오픈 끝(4~8초), 챕터 카드(4~5개), 결말 직전(3~6초).
- 🆕 동물 사진에는 종 이름 캡션("사진 속 동물: 돌묵상어 · 크기 비교용").

## 7. 소리
- ✅ 타자기 소리는 채널 고유 소리 — 바꾸지 않는다.
- ✅ 임팩트는 섞어 쓴다(thud/sub/stab/knock/rumble/metal). boom은 영상당 2번 이하, 심박은 6번 이하.
- ✅ 효과음·배경음은 직접 합성. 글꼴은 무료 글꼴만.
- 🆕 목소리는 **낮고 차분하게 고정**한다. 더 저음으로 내리거나 더 무섭게 꾸미지 않는다(자기 전에 보는 시청자가 많다).
- 🆕 배경음악을 3.5dB 낮추고, 최종 음량은 -14 LUFS로 맞춘다(지금 -13.1).
- ✅ **목소리 도구**: 수익화 신청 전까지 edge-tts를 쓰고, 신청 전에 Azure 정식 음성으로 바꾼다 (2026-11-01 사용자 확정).

## 8. 제목·썸네일·설명란·고정 댓글
- 🆕 제목 = **검색어 대상 + 숫자 1개 + 정체·기록 중 하나 + 꼬리표**([미스터리] 등). '정부·기밀·은폐'를 앞에 두지 않는다(0.79배).
- 🆕 괴물 이름값이 약하면 이름 대신 묘사로("1764년 프랑스, 100명을 덮친 짐승").
- 🆕 "드디어 밝혀진"은 새 사실이 있을 때만. 제목이 약속한 답은 영상 안에서 준다.
- 🆕 제목 틀 3가지를 돌려 쓴다. 직전 2편과 같은 틀 금지.
- 🆕 설명란 첫 줄에 **"이 영상의 사진 N장은 모두 실제 기록 사진입니다(AI 생성 이미지 0장)"**. 시청자 불만은 AI 목소리보다 AI 이미지가 7.5배 많다.
- ✅ 설명란은 5,000자 이내. 넘으면 출처를 라이선스별로 묶는다.
- 🆕 고정 댓글 3단: [질문] → [기록 보충] → [파일 신청 + 다음 파일].
- 🆕 썸네일·제목에 피·시신·훼손 금지. 썸네일 숫자는 대본 숫자와 같아야 한다.

## 9. 수익화·정책
- ✅ 업로드·계정·결제는 사용자가 직접.
- ✅ 설명란에 "내레이션은 AI 음성입니다". 재현(합성)이 들어간 편은 Studio에서 '변경되거나 합성된 콘텐츠'를 '예'로.
- 🆕 채널 정보(About)에 제작 방식(1차 자료 조사·직접 연출·실제 사진·AI 음성)을 적는다 — 반복 콘텐츠 판정 대비.
- 🆕 수익화 신청 전에 '우리가 이렇게 만든다' 설명 영상(5분 이하)을 준비한다(거절 시 이의 제기용).

## 10. 작업 순서와 검사
- ✅ **출력 폴더에 파일번호를 붙인다** (2026-11-01): `output/<번호>_<id>/<번호>_<id>.mp4` — 예 `output/002_loch_ness_short/`, `output/002_nessie_long/`.
  번호는 제목 띠의 `#0NN` 에서 자동으로 읽는다(`engine/paths.py`). 로그는 `output/_logs/`.

1. 벤치마크 확인(같은 주제 경쟁 영상) → 2. 자료 수집(4~5갈래) → 3. 사진 받기(못 받은 목록 확인) → 4. 대본·스펙(생성기 스크립트)
5. 검사: 단어 참조 · 음절 수 · 금지어 · 사진 재사용 · 장면 경계 정지 화면 · 밝기 → 6. 렌더 → 7. 길이·음량 확인
8. 업로드 키트·썸네일 → 9. 사용자 눈 확인 → 10. 업로드 24·72시간 뒤 댓글 점검(정정·신청)

- ✅ 렌더는 한 번에 하나(8GB 맥, 워커 4).
- ✅ 사용자가 화면을 직접 확인한다(저는 사진 내용을 볼 수 없다).
